# 实现与边界

## 文件职责
- `src/rules.mjs`：日志候选、证据分级、规则验证、时间及返还额计算。
- `src/store.mjs`：SQLite 申请、事件、每日预占、配置版本和通知队列。
- `src/newapi.mjs`：云中猫API小站 原身份登录、二次验证、原消费复查与整数额度返还。
- `src/service.mjs`：自助分流、异常审核、手动补偿与共享执行入口。
- `src/server.mjs`：HTTP、服务端会话、权限、请求来源检查和页面资源。
- `public/`：用户工作台与站长管理界面，无第三方 CDN。

## 已确定的行为
当前为正常自助返还、异常审批。消费 type=2、quota>0、completion_tokens=0 仍只是候选筛选；自助额外要求明确空回标记、余额来源、无特殊输出或退款标记、结算等待与自助阈值，并在执行前二次核验。缺乏证据、特殊输出或核验异常进入人工审核。完整规则见 `self-service-2026-11-01.md`。

单条原消费以单实例 request_id 为索引，重新从管理员日志接口精确匹配；不使用用户列表重排的 id。request_id 缺失/同名多条时禁止申请，等待后续部署接入设计解决稳定标识。

申请处理中心按用户合并跨模型申请，并按用户分组分页。用户详情内仍按原申请分页及逐笔审核、执行，不把不同原请求合并成一笔返还。用户分组摘要统计完整分组，不局限当前 30 笔申请。

订阅来源或包含订阅标识的空回必须进入站长审批，普通用户提交不自动发放。站长确认核实金额及依据后，审批通过即走共享执行入口补入用户钱包余额，不恢复原订阅额度。仍逐笔复核原消费、核实金额、规则上限及每日限额；超时转待确认且禁止重发。

金额显示读取 云中猫API小站 `/api/status`，金额确认和规则配置页面刷新读取显示配置。人工执行提交显示金额及配置版本，服务端再次读取配置并用 BigInt 有理数换算回原始整数额度；显示配置变化或超出原站最小精度时拒绝执行，不四舍五入猜测发放金额。

默认全额，金额使用整数 quota。首次配置必须设置渠道、模型、个人/全站每日额度和次数、待审核数量及申请时效，然后开启申请与执行。默认关闭两个开关，白名单为空时不开放，而不是全部允许。

人工审核不推断已退金额；执行前强制填写已核实尚未返还额度和核验说明。金额不能超过原消费与规则上限。自动退款跨记录关联不足时须人工对账。

待审核不占每日限额；执行事务内预占，当日额度按站点时区计算。执行中和结果待确认持续占用；成功计入统计；明确失败释放。每日限额不足保留申请，不截断金额。批量逐笔执行并返回逐笔结果。

云中猫API小站 当前额度增加接口没有持久幂等键：发出请求后出现超时、响应不完整、HTTP 错误或进程中断，一律进入结果待确认；不自动重试。站长依据外部凭据核对后仅登记成功/未到账，登记动作本身不发放。通知使用独立持久队列。

## 接入边界
只连接一个配置的 云中猫API小站 实例。不建立账号或密码表；本地仅保存原用户 id 的申请、会话和审计。登录转发原账号密码，支持源项目的 RSA-OAEP 加密登录与 TOTP 挑战；不绕过验证码、Passkey 或原站限制。不支持的原站挑战须显示错误。

生产接入前仍需用实际部署实例验证接口版本、日志完整性、原站权限和额度到账；没有实际站点凭据时只对本地模拟上游做自动化集成验证，不宣称已完成真实到账验证。
