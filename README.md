# 云响 · NewAPI 补空回

面向一个 NewAPI 实例的独立补偿工作台。复用原站身份，不建立独立账号密码库。使用 Node.js 24 内置 HTTP 与 SQLite，前端原生模块，无构建步骤，服务端无需第三方运行时包；Lucide 图标本地分发，无 CDN。

## 本地启动

**自动部署**：Linux 服务器运行 `bash install.sh`，自动识别 Docker/Compose/host 网络；未找到容器时连接主机或远程 API。部署需要 Docker Engine 与 Compose v2。下载式安装入口见 docs/one-click.md。旧的 `bash deploy.sh` 保留作为手动 bridge 网络部署方式。
部署会自动识别所选容器的主库、日志库配置并保存为受限 secret；仅识别配置，当前日志读取和补款仍走 NewAPI 接口，不代表已直连数据库。

Linux 下载式入口（需先将当前源码发布到仓库）：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/wanfemg/yunxiang-newapi-compensation/main/install.sh)
```

首次交互配置后自动构建、启动和检查接入；再次执行更新源码，保留数据卷与接入配置。无人值守参数见 `docs/one-click.md`。

在本目录执行：

~~~powershell
Copy-Item .env.example .env
# 编辑 .env 中的 NewAPI 地址、管理凭据与管理用户 ID
node --env-file=.env src/server.mjs
~~~

入口为 http://127.0.0.1:3210 。没有配置上游时登录页正常打开，但不提供虚假用户或消费数据。管理凭据须具备读取日志、查询用户与增额的原站权限；不是推理 API 的 sk- 密钥。原站管理员仍受原站角色与能力限制。

## 当前实现

- NewAPI 账号密码登录，兼容本地源项目 RSA-OAEP/AES-GCM 密码封装与 TOTP 挑战；会话仅服务端保存原站短期访问令牌，浏览器使用 HttpOnly Cookie。
- 用户概览、可补/待核实日志、批量申请、申请详情、成功返还记录与规则说明。
- 正常消费自助补额度，异常消费进入审批；服务端确定金额，二次核验后共享去重、事务限额和 unknown 冻结机制。默认等待 60 秒，自助原消费上限 100000 quota，后台可配置。详见 docs/self-service-2026-11-01.md。
- 站长概览、日志筛选、单笔/批量手动发起补偿、人工审核、逐笔核验金额后批量执行、异常核对。
- 渠道和模型白名单、用户组和禁用用户、申请时效、消费起止、跨午夜开放时间、单笔上限、个人/全站每日额度和笔数、待处理数量限制。
- 用户/模型/渠道/日期补偿统计，规则版本和原消费快照，操作审计。
- 钉钉官方加签机器人、通知总开关与事件开关、测试发送、持久队列和最多五次重试。机器人密钥加密落盘；密钥文件和数据库必须一起备份并限制文件访问。

## 首次配置顺序

1. 配置 .env 并验证原账号登录。
2. 使用原站站长账号进入管理界面，核对渠道 ID 和完整模型名。
3. 配置个人/全站每日额度、次数和申请时效，再开启申请。限额初始为 0，申请与执行初始关闭。
4. 核对真实消费的完整字段、request_id 唯一性、实际扣费和自动退款情况。
5. 使用可核验的正常/异常消费分别验证自助、审批、到账和异常对账，核对自助开关、单笔阈值与结算等待，再开启执行。执行开启后符合自助条件的用户提交会立即发起返还，不再等待站长审批。
6. 配置钉钉签名机器人及通知事件，测试发送。

## 重要边界

- 零输出 token 只是候选；正常记录还须具备明确空回标记、余额来源、结算等待、无特殊输出或退款标记并通过规则核验才能自助返还，异常记录走审批。未登记的外部人工返还无法从本系统自动发现，需统一返还入口或同步上游退款标记。
- 钱包消费可按规则返还至钱包。订阅空回转站长审批，站长确认核实金额后审批通过即调用钱包增额接口，不恢复原订阅额度。历史缺失资金来源的记录必须人工核实。
- 依赖管理员日志接口的 request_id 精确查询；标识缺失、重复或历史记录删除时禁止执行，不使用用户页面重排的日志 ID。
- 用户日志查询按账号与筛选条件持久缓存，15 秒内重复查询或翻页复用结果，并发同步合并；之后按上次同步时间增量拉取，并重查最近 5 分钟覆盖延迟写入。每 15 分钟在下次查询时重新核对完整范围，防止更晚的历史日志遗漏。同步失败不推进游标、不返回伪造的“无记录”。缓存仅用于查询，申请及发放前仍独立读取原始日志。
- 已补成功记录在用户查询分页前排除，保留在补回记录；未申请记录保留，已申请记录关联最新本地进度且禁止再次申请。管理员原始消费查询保持实时，仍可核查成功记录。分页总数是排除成功项后的消费数量，界面候选筛选仍按页计算。单个查询范围最多同步 10000 条消费，超出时须缩小时间范围；缓存保留最多 200 个查询范围，并在写入时清理超过一天未更新的范围，不删除申请或账本。
- 原站增额接口没有业务幂等键：一次发出后结果不明或进程中断转为待确认，禁止自动重发。只有人工凭据确认未到账并重新审核后才允许再执行。
- 原站短期访问令牌失效后重新登录；首版不保存刷新令牌。验证码/Passkey/OAuth-only 等原站登录流程尚未完整接入，不会绕过原站限制。
- 管理配置和数据仅针对一个 NewAPI 实例，创建数据后不得直接切换 NEWAPI_URL 指向其他实例；多实例及实例迁移尚未实现。
- 应用进程为单实例，使用本地持久数据目录；不支持多个副本共享 SQLite。生产必须配置 HTTPS 入口与 PUBLIC_ORIGIN，并限制数据目录权限。反代不应缓存 /api，Host 绑定默认仅本机。
- 生产没有任何内置演示账号。test/preview.mjs 仅为明确标识的本地模拟上游，数据不落盘，不用于生产。

## 管理端操作

- 补偿规则设置底部的数据库清理支持预览与二次确认：缓存默认保留 7 天，已结束通知默认保留 30 天，旧快照可选保留 30 天且至少保留最新 3 份。待发送通知、申请、发放去重账本、审计、密钥、数据库主文件与 WAL 不删除。快照仅清理账本旁 `backups/` 内由备份命令生成的命名格式文件，忽略链接及其他文件，预览后改变的文件跳过。清理预览绑定管理员、5 分钟有效且单次使用；发放中禁止执行。可选 SQLite 空间整理，不手动删除 WAL，低峰操作以免短暂阻塞请求。清缓存后重新同步消费仍受账本去重保护，清理不会操作 NewAPI 原站数据。

- 时间配置只需最近 N 天、结算时区和每日重置时间（默认 00:00），保存简化配置后按服务器当前时间滚动读取日志，不再使用固定消费起止及每日开放时段。用户组从 NewAPI `/api/group/` 读取并勾选，未选表示全部组。每日额度和次数为本工具的补偿限额，不是 NewAPI 消费限额；金额按原站显示单位提交，服务端精确换算并核验显示版本。实际补回 2、日限额 300 时剩余 298，每条消费算一次，执行中及待对账预占。修改重置时间会按持久化执行时间重算结算日，历史账本不会被清空。

- 最近申请展示申请用户、预计或实际补偿额度、状态；详情包含模型、原请求、扣费及处理时间线。上游日志没有保存的提示词或响应正文不会被还原或虚构。
- 原始消费查询用于核对原始扣费、空回证据与申请资格；补偿统计按用户、模型、渠道汇总申请及成功额度，支持逐笔下钻，两者不重复统计口径。
- 申请处理中心分待审核、待执行、成功、待对账、失败和驳回板块，同一用户跨模型申请合并显示，按用户分页，展开后逐模型查看每笔申请。合并不改变原请求标识、审核状态和发放幂等性；结果不明仍禁止盲目重发。
- 可补渠道和模型从 NewAPI 管理接口读取，需要站长的 ChannelRead 权限。客户端只接收渠道 ID、名称、状态和模型列表，不接收渠道密钥；普通用户无渠道目录访问权限。模型限制可关闭，渠道限制仍生效。
- 已删除或下架模型、停用渠道的历史消费转人工审核，仍受所选渠道、归属、时效、额度及订阅人工审批规则约束。目录读取失败不会自动发放。
- 页面金额、填写额度和钉钉 Markdown 通知读取原站 `/api/status` 的显示单位及汇率，内部账本和发放仍为整数额度。确认金额时刷新显示配置，浏览器提交显示金额及配置版本，服务端重取配置并用整数有理数精确换算；配置变化或超出最小计费精度则拒绝发放。原站显示配置读取失败时不猜测换算比例。
- 申请详情、模型展开项、时间线、操作确认、下拉菜单及日期时间弹层使用统一毛玻璃组件；保留原生表单值与键盘输入，日期时间弹层不依赖操作系统的选择器样式。
- 钉钉通知包含申请编号、用户、模型、原请求、补偿额度、状态、处理说明和时间。本地验证使用模拟上游，未验证真实机器人送达。

管理端浏览器回归：设置 `PLAYWRIGHT_MODULE_PATH`、`PREVIEW_PORT=3213` 和 `PREVIEW_DEMO_DATA=1` 后运行 `node test/ui-admin.mjs`。
